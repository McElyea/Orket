# Core 0.7.7 source checkpoint

Status: Scoped Windows source proof complete; historical failures and stated limits retained.
Recorded: 2026-10-05 (America/Denver)

## What changed

This patch repairs demonstrated workflow blockers: artifact QA no longer acquires
app-only design inputs; Windows text writers preserve submitted UTF-8 line endings;
and the local response validator distinguishes Markdown inside JSON arguments
from fences around the tool envelope. The response parser owns that lexical rule.
The small-team refusal no longer recommends an ineffective threshold change.

The twelve-card programming challenge now declares completion acceptance over its
existing requirements, fixtures, commands and assertions. A prepared CLI adapter
reuses the canonical RuntimeVerifier and retains inner process evidence. The
recipe declares the existing one-turn history window to fit the selected 8K
server while preserving required file context and complete retained transcripts.
It seeds no solution code. CLI benchmark checks now separate wrong answers from
unequal replay outputs; both checks remain required for task success.

The long streaming attempt exposed an abandoned-reader race in the scenario
harness. Poll deadlines now retain one pending WebSocket receive; socket closure
precedes reader settlement. This avoids losing late completion events without
prefetching, relaxing assertions or changing runtime/provider deadlines.

A normal shell resolved the older global core/SDK 0.7.1 installation. A stable
project `.venv` now contains the current editable development pair, with Windows
creation and activation documented in the root README and contributor guide.
Activate it in each shell or invoke its executables explicitly. The global
installation, provider configuration, operator board and model server are preserved.

Use the [prepared workflow recipes](../../../examples/stored_workflows/README.md)
and [readiness contract](../../specs/WORKFLOW_BENCHMARK_READINESS.md).
The [contract delta](../../architecture/CONTRACT_DELTA_WORKFLOW_RECOVERY_2026-10-04.md)
records the scoped migration and unchanged acceptance boundaries.

- `compatibility_status`: `breaking`
- `affected_audience`: `operator_only`
- `migration_requirement`: `required`

Prepare a new challenge directory, retain its seeded acceptance adapter, install
development dependencies including pytest, and apply the printed runtime
environment before launching the CLI or API. Existing workspaces and historical
reports are not rewritten. Exact writes now retain supplied LF/CRLF bytes.

This is a patch source checkpoint with local installed-candidate verification.
The accepted public core/SDK pair remains 0.7.2; no replacement wheel, empty
release, new SDK version or full release-pair campaign is proposed. Stability is
bounded by the specific live and native checks below.

seconds; those are not successful-run timing baselines for the recovered challenge.

model-quality proof. HTTP admission/transport samples are not completed jobs.

its generated pytest tests are bounded by their generated assertions.
