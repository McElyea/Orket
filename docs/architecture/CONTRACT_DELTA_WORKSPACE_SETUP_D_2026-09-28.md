## Delta

The canonical three workspace setup services formerly submitted native metadata,
directory and traversal work without a retained complete-stage owner. Their
individual `AsyncFileTools` writes already retain open/write/close; cancellation
there may still end the surrounding stage before its remaining files and
validation. Raw metadata cancellation can abandon its native operation entirely.
Mutable roots/tool bindings can also change after the first await.

Each public `ensure` resolves its unchanged detached specification, captures its
standard root and AsyncFileTools capability using the existing capture authority,
then invokes the unchanged remaining stage body on an explicitly constructed
canonical service under `run_owned_io(preserve_failure=True)`. No generic self
clone, new settlement loop, retry, workspace policy or transaction is added.
The existing specification renderer owns content; no borrowed organization or
profile object is retained for later input decisions.

The complete admitted stage settles before caller interruption escapes. Success
after interruption is discarded. Native and validation failure takes precedence,
with existing exception types and messages. Existing files are preserved; a later
failure does not undo earlier created directories/files. The coordinator remains
between stages after interruption and cannot label that stage completed.

Ordinary relative roots bind before suspension; drive-relative roots are refused
by the existing file-root policy before effects. Workspace and file-tool roots
retain their separate existing roles; no new equality/containment policy replaces
their existing checks. These are standard concrete setup inputs, not a guarantee
for arbitrary subclasses or bound instance hooks. Custom setup implementations
continue to enter through `OrchestratorSupportServices`' existing construction
seam, with their own ownership duties.
