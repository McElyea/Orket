## Outcome

Slices 1 and 2 are implemented for one deterministic CLI-only path. A
catalog-resolved SDK workload runs in a real child process, makes framed calls
to the real host broker backed by a deterministic fixture provider, completes
two separately admitted and fenced iterations, receives the first result as
materialized input to the second, and reaches verifier-backed terminal truth.

The proof is live process/integration proof of the deterministic child/broker
path. It is not live-model, effect, approval, recovery, multi-model, API,
supervisor, or continuous-operation proof.

## Claim Limits and Remaining Work

1. The deterministic provider is an explicit fixture and does not contact
   Ollama or prove provider availability, model identity, quality, or usage.
2. The reference extension is a repo-owned template/local fixture, not a hosted
   or published external repository.
3. No effect proposal is approved or executed on this path.
4. Restart and crash proof covers interrupted dispatch, child disconnect, and
   fail-closed uncertainty, not post-effect reconciliation.
5. Cross-process CLI cancellation cannot directly signal a child owned by a
   different CLI process. It durably fences and closes the run; the in-process
   operator service owns active child cancel/reap.
6. Slices 3-7 and B2-gated supervisor lifecycle composition remain open.
